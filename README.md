# Terra–Luna Development

一个用于软件开发协作的 Codex 技能：由 **Terra** 保留全局判断、架构决策和最终验收；将边界清晰、可独立验证的工作包交给 **Luna** 执行。

它适合把“需要综合判断的工作”和“可以明确交付的执行性工作”分开处理，在保持主代理对结果负责的同时，提高探索、实现和验证的效率。

## 适用场景

当任务包含软件设计、实现、调试或代码审查，并且其中一部分可以被清楚地限定范围时，使用此技能。

适合交给 Luna 的工作包括：

- 在指定范围内检索代码、收集证据或整理日志；
- 按既定设计进行机械性修改；
- 运行确定性的测试、构建或检查命令；
- 对根因已经确认的问题实施小范围修复。

以下工作应由 Terra 直接完成：

- 架构、接口、数据模型和依赖选型；
- 原因尚不明确的故障诊断与修复策略；
- 安全、权限、兼容性和破坏性操作的判断；
- 审查变更是否满足目标，并作出最终验收。

对于只有一两个已理解文件的小改动、简单命令或文字修订，通常直接处理更合适，无需委派。

## 工作流程

### 1. 先明确边界

在编辑前，Terra 应明确以下内容：

- 目标与非目标；
- 受影响的接口、格式或文件；
- 兼容性要求；
- 是否存在安全风险或不可逆操作。

### 2. 将可验证的工作包交给 Luna

每个委派任务必须是独立、有限且可验证的，并使用完整任务契约。任务需要明确目标、上下文、范围、允许修改的文件、禁止事项、验收条件和验证命令。

任务契约模板位于 [references/task-contract.md](references/task-contract.md)。若需求含糊、发现未知故障、需要改变架构或接口，Luna 应停止并请求 Terra 决策，而不是自行扩大范围。

### 3. 由 Terra 审查并验收

Luna 返回结果后，Terra 需要检查变更内容和工作区状态，并确认：

- 变更符合既定目标和验收标准；
- 验证命令确实通过，且结果与任务相关；
- 没有超出范围的重构、接口变化或意外修改；
- 没有遗留需要进一步决策的问题。

测试通过是重要证据，但不等同于自动验收。

## 安全与 Git 边界

除非用户明确授权，本技能不会执行提交、推送、变基、重置、修订提交、打标签或删除分支等 Git 操作，也不会进行破坏性的数据或配置操作。

更多委派与升级规则请参阅 [references/delegation-policy.md](references/delegation-policy.md)。
